# 2026-09-10 真机恢复记录

## 环境

- 机型：`SM-S937U1`
- CSC：`XAA/XAA`
- 系统：Android 16，2026-08-05 安全补丁
- 固件：`S937U1UES9CZF9`
- SIM：DSDS，两个逻辑卡槽均显示中国移动

## 结果

恢复前的脱敏快照 `logs/20260910-183406-before-recovery.json` 显示 `gsm.network.type=LTE,LTE`。

ADB 自动驱动三星 Service Mode 执行了以下项目：

1. `SET DEFAULT LTE BAND`
2. `REMOVE NR5G PRUNE`（重跑时已能识别 `RESTORE NR5G PRUNE`，证明解除状态已生效）
3. `REMOVE ONLY NR WHITELIST`
4. `SA/NSA ENABLE`
5. `REMOVE SA PERMIT LIST`

完成后脚本发起重启。Windows 的 USB 设备枚举在本次重启后延迟，导致同一次进程里的自动回连超时；重新插拔并解锁手机后，单独运行 `verify-5g.cmd` 成功。脱敏快照 `logs/20260910-184421-verification.json` 显示 `gsm.network.type=NR_SA,LTE`，SIM 1 已恢复中国移动 5G SA。

## 新固件兼容性修正

`dumpsys window` 在这版系统上同时返回一条空焦点和一条真实的 Service Mode 焦点。旧实现只取第一条，因而会把已经打开的工程菜单误判成失败。现在会合并所有焦点行进行包名判断，并对菜单加载做有上限的轮询。

Service Mode 的菜单文字和层级在本次实测中没有变化。另行修正了两个自动化问题：操作日志遇到短暂文件锁时会重试且不再中断基带设置；根目录一键入口会传入 `-AssumeYes`，型号校验通过后直接执行。

所有持久化快照均不包含 IMEI、IMSI、ICCID、电话号码、ADB/USB 序列号或小区位置。
